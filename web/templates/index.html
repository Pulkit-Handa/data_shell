Bad data stops here.

Data Shell is the publication boundary for external feeds. Enforce the rules before records reach the systems that depend on them: cast strictly, reconcile every row, and publish only what can be accounted for. Every delivery ships with signed evidence you can verify offline.

The failure

A pipeline succeeded. The published data was still wrong.

Most ingestion failures are not crashes. The job completes, the file lands, and a defective record reaches a settlement, a filing, or a partner reconciliation. Nothing at the boundary made a publication decision — and nothing recorded one.

Copy-through pipeline

The job copies what it received.

A successful process is treated as a trusted artifact.

  • ×A validation report describes bad rows after the write; the write is not stopped.
  • ×Rows that fail a check and rows that pass land in the same delivered file.
  • ×There is no per-record decision trail: which rule held which row, from which feed.
  • ×Proving what was delivered means reconstructing history by hand.

Data Shell boundary

Nothing publishes until every row is accounted for.

The publication decision moves to the last point where it can be enforced.

  • ✓Strict per-row casting refuses values that cannot be realized instead of coercing them.
  • ✓Row and batch rules quarantine records with the exact rule that stopped them.
  • ✓Zero-deficit reconciliation gates the run: read = refused + held + delivered.
  • ✓Atomic publication commits the target, lineage, and a signed certificate together.

The distinction is not better validation. It is where the publication decision is made — and whether that decision leaves evidence an operator, an auditor, or a counterparty can verify without trusting anyone’s account.

The mechanism

Four checks. One decision. Any stage can stop the run.

Records pass through four sequential gates. If one fails, the run terminates before a partial dataset is published, and the terminal outcome is recorded.

  1. 01 / STRUCTURAL

    Strict cast at the door

    Each record is cast against the declared schema, per row. A value that cannot be realized is refused and indexed — never silently coerced into something it is not.

  2. 02 / SEMANTIC

    Row and batch rules

    Vectorized row rules run on Polars; batch rules run on DuckDB, out-of-core in streaming mode. The fast path engages only on chunks that already match the schema.

  3. 03 / RECONCILIATION

    The arithmetic must foot

    Read = refused + held + delivered, with unaccounted_for as a hard zero. A single unaccounted row refuses the run instead of publishing a partial dataset.

  4. 04 / PUBLISH

    Atomic and crash-recoverable

    Target, lineage, and certificate commit through a write-ahead journal and are recovered at startup. Quarantine evidence survives the rejection.

exit 0 Published. Reconciled and delivered with a certificate.
exit 2 Refused by policy. No rows published.
exit 1 Engine failure. Nothing published; your scheduler sees a failed job.

{
  "apiVersion": "daas/v1",
  "kind": "DataProduct",
  "metadata": { "name": "vendor-settlements", "version": "1.0.0" },
  "spec": {
    "sources": [{
      "type": "LOCAL", "format": "jsonl",
      "schema": [
        { "name": "settlement_id", "polars_type": "Utf8",    "nullable": false },
        { "name": "amount",        "polars_type": "Float64", "nullable": false },
        { "name": "currency",      "polars_type": "Utf8",    "nullable": false }
      ]
    }],
    "quality": {
      "behavior": "DROP_ROW",
      "rules": [
        { "rule_id": "amount-positive",  "check": "GREATER_THAN",
          "column": "amount", "value": 0 },
        { "rule_id": "currency-settled", "check": "ALLOWED_VALUES",
          "column": "currency", "value": ["USD", "EUR", "GBP"] }
      ],
      "batch_rules": [
        { "rule_id": "not-partial", "check": "MIN_ROW_COUNT", "value": 3 }
      ]
    }
  }
}

What the contract buys you

  • ReproducibleA versioned artifact your team reviews, diffs, and rolls back — not application logic buried in a service.
  • PortableThe same contract runs from the CLI, the HTTP gateway, or an Airflow task. Identical verdict.
  • AuditableEvery held row names its rule; every refused row names its structural reason.
  • Fail-closedIf the feed cannot be accounted for, nothing is delivered.
  • ExtensibleShip your own row and batch check types as plugins; built-ins cannot be shadowed.

Evidence

          
Bounded by arithmetic and a signature.

          

            Three guarantees matter when an external feed crosses into systems you are accountable for.
            Each is implemented in the engine and observable from a run you can reproduce.
          

        


        

          

            
01 · Reconciliation

            
Nothing publishes unaccounted for.

            
Rows read must equal delivered + held + refused. If a single row cannot be accounted for, the run refuses to publish rather than ship a partial dataset.

            
Reproduce: datashell demo --scenario full
1,000 = 900 delivered + 60 held + 40 refused · unaccounted 0

          

          

            
02 · Publication

            
No partial batches, even after a crash.

            
The target, an immutable lineage artifact, and the certificate commit together through a write-ahead journal. Interrupted publications are recovered at startup.

            
Verify: publication atomicity and recovery paths are covered by the test suite — pytest collects 522 tests.

          

          

            
03 · Integrity

            
A flipped byte fails verification.

            
A Merkle root binds the contract, source bytes, delivered bytes, and quarantine artifacts; the certificate is signed with HMAC-SHA256, or Ed25519 for third-party verification.

            
Reproduce: datashell demo
AUTHENTIC → TAMPERED_UNDERLYING_ARTIFACTS → AUTHENTIC

What the certificate proves — and what it does not

            
    
              
  • IntegrityThe delivered bytes are the bytes the engine validated. datashell verify recomputes every hash and the signature offline; a single modified byte fails it.
    • 
              
  • Authorship under a keyHMAC-SHA256 proves possession of the shared secret. Provision an Ed25519 key and any holder of the public key can verify without sharing one.
    • 
              
  • Not sender identityThe certificate does not prove who sent the feed. Pair it with your own trust anchor and review process.
    • 
              
  • Real values, not marketing copyThe live demo above renders the actual certificate excerpt from the run you start — merkle root, payload hashes, and reconciliation included.
    •

For engineers

          
One engine. The same verdict from every surface.

          

            Data Shell does not replace your orchestrator, storage, or alerting. It owns exactly one
            decision — does this batch cross the boundary, and with what evidence — and returns the same
            terminal record whether you call it from a shell, a scheduler, a service, or an SDK.

Deployment maturity

          
What is tested, what is designed, and what is still an assumption.

          

            The boundary is explicit about its operating envelope. An approver should know these facts
            before a pilot, not after one.
          

        


        

          

            
AreaStatus

            
              

                Enforcement behavior
                Tested in CI: casting refusals, rule holds, footing gates, REJECT_RUN parity, publication atomicity, recovery, tamper detection, RBAC, sandboxing, and rate limits. 522 collected tests; bandit zero-findings policy; OSV dependency audit.
              

              

                Reconciliation & atomicity
                Hard gates, not warnings: zero-deficit accounting and write-ahead publication. Observable in every certificate and covered by the suite.
              

              

                Deployment topology
                The reference deployment is intentionally single replica and single worker. The credential registry, rate limiter, and demo concurrency limits are process-local; scale-out requires shared stores before running multiple replicas.
              

              

                Resource limits
                20 GiB per upload (configurable), bounded request bodies, disk-headroom preflight, and a demo artifact quota. Concurrency is bounded per worker and per replica.
              

              

                Performance envelope
                Measured on one development machine by committed harnesses. Reproducible by you; not a guarantee for your environment.
              

              

                Certificate semantics
                Proves integrity and authorship under the signing key; it does not prove sender identity. Use Ed25519 with a published key for third-party verification, and pair it with your own trust anchor.
              

              

                Not yet established
                Production hardening beyond the reference topology: multi-replica operation, live billing integration, real-collector OpenTelemetry export, and your deployment-specific threat model. A pilot exists to establish them.
              

              

                Certification
                None claimed. Code-level checks are not a substitute for a deployment-specific threat model and independent review.

Acceptance criteria for a first pilot

            
    
              
  • ReconciliationEvery run reports read = delivered + held + refused with zero unaccounted rows.
    • 
              
  • AttributionEach held record names its rule; each refused record names its structural reason.
    • 
              
  • Evidencedatashell verify returns AUTHENTIC_AND_UNMODIFIED for the certificate you just produced.
    • 
              
  • Fail-closedA deliberately tampered artifact fails verification, and a footing mismatch refuses the run.
    • 
              
  • IntegrationOne scheduled job is replaced with the boundary call; exit codes and JSON stay in your scheduler’s hands.
    •
